# Security and access control
**Implemented:** extension whitelist (.nii/.nii.gz) + magic-byte/gzip header sniffing; server-chosen file names (`<role>.nii[.gz]` inside a random-UUID folder), `secure_filename` for display names, path containment checks on downloads; upload size limit (`MAX_UPLOAD_MB`, HTTP 413); CSRF (Flask-WTF) on all POSTs (tested); parameterised SQL; no absolute paths in UI/metadata; `torch.load(weights_only=True)` by default (unsafe pickle only with explicit env flag); secrets from env (random per-process key if unset, with warning); audit events table (no passwords/images logged); uploads and outputs separated; `partial_*` temp-file cleanup at start; delete removes DB rows and files and reports partial failures; `retention` setting exists but **automatic retention cleanup is not implemented**.
**NOT implemented:** user registration/login, password hashing, per-user ownership of examinations. The default deployment is single-user on localhost (`HOST=127.0.0.1`). Anyone who can reach the port can see all examinations – do not expose it to a network. Adding Flask-Login + an `owner_id` column and per-route ownership checks is future work.
No formal security audit; not HIPAA-compliant; not clinically certified.
